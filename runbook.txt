WHORL — OPERATIONAL RUNBOOK
=============================

PURPOSE
-------
Whorl is the declarative routing and data-weaving layer for the bleaknarratives
ecosystem. It contains the Loom implementation — Celtic knot-inspired
cryptographic topological data weaving.

# Idea: the "tensile-testing mesh" for quantized small models on RAM-limited
# devices. Local quant pass runs on-device; when the sampler's confidence on the
# next token falls below a gate it has hit a "quantization hole" (quant loss
# collapsed two semantic vectors to one coordinate). Whorl SLICES: sends the
# context slice to a dense FP16 cloud model (Groq gpt-oss-120b via the Boardroom
# router -> key pool + 429 backoff) which returns a corrected token, merged back.
# ~95% compute stays local -> the phone feels like a big model.
#   Offline selftest  : python3 whorl/slice/whorl_slice.py --selftest
#   Offline slice     : python3 whorl/slice/whorl_slice.py --prompt "..." 
#   Live Groq slice   : python3 whorl/slice/whorl_slice.py --prompt "..." --live
# Local backends      : reference (deterministic sim, default) | llama-server (GGUF)
# Tests               : python3 -m unittest tests.test_slice
# Note                : llama-server backend stubbed pending a llama.cpp binary build;
#                       reference backend stands in with synthetic quant-hole injection.
# Internals: ReferenceQ4Pass injects holes on hole_spacing; SliceController gates on
# confidence; CloudFp16Pass loads Boardroom router via importlib (needs GROQ key in env).
